================================================================================
           دليل وخطوات العمل الجماعي على GitHub لمشروع VisionCraft DIP Studio
================================================================================

هذا الدليل مخصص لأعضاء الفريق الثلاثة لشرح تقسيم الملفات بدقة وخطوات رفع كل قسم
إلى مستودع GitHub المشترك عبر الفروع (Branches) وطلبات الدمج (Pull Requests)
لضمان ظهور مساهمة كل طالب أمام أستاذ المادة وتفادي أي تعارضات (Conflicts).

رابط المستودع على GitHub:
https://github.com/ShoaibAlhashaDev/visioncraft-dip-studio.git

--------------------------------------------------------------------------------
1. جدول تقسيم المسؤوليات والملفات بين الطلاب الثلاثة
--------------------------------------------------------------------------------

[الطالب 1] - مهندس الباك إند ومعالجة الصور (Backend & Python Microservice)
------------------------------------------------------------------------
- اسم الفرع الخاص به في Git:
  feature/backend-engine
- المجلدات والملفات المسندة إليه حصراً:
  • app/Http/Controllers/ImageProcessingController.php
  • routes/api.php
  • routes/web.php
  • python_engine/  (المحرك بالكامل: core/ و app/server.py و requirements.txt)
  • database/
- المهام المطلوبة:
  1. ضبط وسيط الـ API في لارافل لاستقبال وتمرير طلبات معالجة الصور.
  2. تطوير فلاتر وخوارزميات معالجة الصور الرقمية (DIP) في بايثون (OpenCV / NumPy).
  3. إدارة منافذ الاتصال وسرعة استجابة المحرك.


[الطالب 2] - مهندس الواجهات وتجربة المستخدم (Frontend & UI/UX Developer)
------------------------------------------------------------------------
- اسم الفرع الخاص به في Git:
  feature/frontend-studio
- المجلدات والملفات المسندة إليه حصراً:
  • resources/views/welcome.blade.php  (وأي ملفات blade فرعية)
  • public/js/       (أكواد الجافاسكربت، معالجة الـ Canvas، التفاعل، الـ AJAX)
  • public/css/      (ملفات التنسيق والتصميم والألوان)
  • public/accessories/  و  public/backgrounds/  و  public/samples/
- المهام المطلوبة:
  1. تصميم الواجهة الرسومية وتوزيع القوائم وأشرطة الأدوات.
  2. برمجة التفاعل مع أدوات الرسم والـ Sliders وتحميل وحفظ الصور.
  3. ربط أزرار الواجهة بالباك إند عبر طلبات AJAX Fetch وعرض مؤشر التحميل.


[الطالب 3] - مهندس التوثيق وهندسة البرمجيات وضمان الجودة (QA & Documentation Lead)
--------------------------------------------------------------------------------
- اسم الفرع الخاص به في Git:
  docs/system-documentation
- المجلدات والملفات المسندة إليه حصراً:
  • README.md
  • docs/  (مثل: docs/SRS.md و docs/RISK_MANAGEMENT.md ومخططات الـ UML)
  • AGENTS.md  و  CLAUDE.md  و  CONTRIBUTING.md
  • tests/  (اختبارات النظام وتقارير فحص الجودة)
- المهام المطلوبة:
  1. توثيق المشروع كاملاً في README.md (المتطلبات، طريقة التشغيل خطوة بخطوة).
  2. إعداد وتضمين مخططات هندسة البرمجيات (Use Case, System Architecture, Sequence).
  3. توثيق مدخلات ومخرجات الـ API وسجل المخاطر (Risk Matrix).
  4. إجراء الفحص النهائي للنظام وكتابة سيناريوهات الاختبار (Test Cases).


================================================================================
2. الخطوات العملية لكل طالب لرفع عمله إلى GitHub بشكل سليم
================================================================================

----------------------------------------------------------------------
خطوة هامة جداً للجميع قبل البدء (إعداد هوية الطالب في Git):
----------------------------------------------------------------------
حتى يسجل GitHub كل التعديلات باسمك وبريدك الرسمي ويراها الدكتور في قائمة
الـ Contributors، افتح موجه الأوامر (CMD أو Terminal) ونفذ الأمرين التاليين
(استبدل بالاسم والإيميل المسجل بهما في حسابك على GitHub):

git config user.name "YourFullName"
git config user.email "your-github-email@example.com"


----------------------------------------------------------------------
خطوات [الطالب 1] - مطور الباك إند ومحرك بايثون:
----------------------------------------------------------------------
1. افتح موجه الأوامر داخل مجلد المشروع وتأكد أنك محدث لآخر نسخة:
   git checkout main
   git pull origin main

2. أنشئ فرعك الخاص وانتقل إليه:
   git checkout -b feature/backend-engine

3. قم بكتابة وتعديل الأكواد في ملفات الباك إند الخاصة بك فقط:
   (app/, routes/, python_engine/, database/)

4. أضف الملفات التي قمت بتعديلها:
   git add app/ routes/ python_engine/ database/

5. احفظ التعديلات (Commit) برسالة واضحة:
   git commit -m "feat(backend): implement image processing algorithms and connect api"

6. ارفع فرعك إلى GitHub:
   git push -u origin feature/backend-engine


----------------------------------------------------------------------
خطوات [الطالب 2] - مطور الواجهات الأمامية والـ JS:
----------------------------------------------------------------------
1. افتح موجه الأوامر داخل مجلد المشروع وتأكد أنك محدث لآخر نسخة:
   git checkout main
   git pull origin main

2. أنشئ فرعك الخاص وانتقل إليه:
   git checkout -b feature/frontend-studio

3. قم بكتابة وتعديل الواجهات والأكواد الخاصة بك فقط:
   (resources/views/, public/js/, public/css/, public/accessories/)

4. أضف الملفات التي قمت بتعديلها:
   git add resources/views/ public/js/ public/css/ public/accessories/

5. احفظ التعديلات (Commit) برسالة واضحة:
   git commit -m "feat(frontend): enhance studio UI layout and canvas event handlers"

6. ارفع فرعك إلى GitHub:
   git push -u origin feature/frontend-studio


----------------------------------------------------------------------
خطوات [الطالب 3] - مسؤول التوثيق وهندسة البرمجيات:
----------------------------------------------------------------------
1. افتح موجه الأوامر داخل مجلد المشروع وتأكد أنك محدث لآخر نسخة:
   git checkout main
   git pull origin main

2. أنشئ فرعك الخاص وانتقل إليه:
   git checkout -b docs/system-documentation

3. قم بكتابة ملفات التوثيق والمخططات الخاصة بك فقط:
   (README.md, docs/, AGENTS.md, CLAUDE.md, CONTRIBUTING.md, tests/)

4. أضف الملفات التي قمت بتعديلها:
   git add README.md docs/ AGENTS.md CLAUDE.md CONTRIBUTING.md tests/

5. احفظ التعديلات (Commit) برسالة واضحة:
   git commit -m "docs: add comprehensive documentation, uml diagrams, and risk matrix"

6. ارفع فرعك إلى GitHub:
   git push -u origin docs/system-documentation


================================================================================
3. خطوة الدمج الرسمية على GitHub (Pull Request)
================================================================================
بعد أن يرفع كل طالب فرعه إلى GitHub، تكتمل الخطوة الأهم أمام الدكتور:
1. ادخل إلى صفحة المستودع على المتصفح:
   https://github.com/ShoaibAlhashaDev/visioncraft-dip-studio
2. ستظهر لك لافتة صفراء بالأعلى تذكر فرعك الجديد؛ اضغط على:
   [ Compare & pull request ]
3. اكتب عنواناً لما قمت به (مثال: إضافة واجهة شريط الأدوات أو خوارزميات المرشحات).
4. في صندوق الوصف، اكتب قائمة بالنقاط التي أنجزتها.
5. اضغط على الزر الأخضر: [ Create pull request ].
6. يقوم قائد الفريق أو الزملاء بمراجعة الكود والضغط على [ Merge pull request ].


================================================================================
4. قواعد ذهبية لتجنب المشاكل والتعارضات (Important Tips):
================================================================================
1. [ممنوع الرفع المباشر على main]: يجب أن يمر كل عمل عبر فرع خاص به ثم Pull Request.
2. [التحديث اليومي المستمر]: قبل أن تبدأ بالعمل يومياً، انتقل لفرعك ونفذ الأمر:
   git pull origin main
   لكي تنزل التعديلات الجديدة التي دمجها زملاؤك دون حدوث أي تعارض.
3. [التزام كل طالب بمجلده]: طالما أن كل طالب يضيف ويعدل في مساره المحدد في الجدول،
   فلن يحدث أي تعارض (Conflict) في Git نهائياً.
4. [مراجعة التقييم]: قبل تسليم الرابط للدكتور، افتحوا تبويب:
   Insights -> Contributors
   للتأكد من ظهور أسماء الطلاب الثلاثة بنسب متقاربة في المشروع.
